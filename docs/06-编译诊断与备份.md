# 06 - 编译、诊断、导出与备份

---

## 1. 编译：`ICompilable` 服务

编译**不是** `PlcSoftware` 的方法，而是通过服务接口取得：

```csharp
var compilable = plcSoftware.GetService<ICompilable>();
CompilerResult result = compilable.Compile();
```

PowerShell 5.1 里必须反射取泛型方法：

```powershell
$compilable = Get-TiaService $plc ([Siemens.Engineering.Compiler.ICompilable])
if (-not $compilable) { throw 'ICompilable service not available.' }
$result = $compilable.GetType().GetMethod('Compile').Invoke($compilable, $null)
```

### `Siemens.Engineering.Compiler` 命名空间只有 6 个公开类型

```
CompileProvider                     ← 唯一实现 ICompilable 的类
ICompilable                         ← interface { CompilerResult Compile(); }
CompilerResult
CompilerResultMessage
CompilerResultMessageComposition
CompilerResultState                 ← enum
```

### ⚠ 两个常见命名错误

| 容易写错的名字 | 实际名字 |
| --- | --- |
| `CompileResult` | **`CompilerResult`** |
| `CompileResultMessage` | **`CompilerResultMessage`** |
| `CompileOptions` | **不存在**（`Compile()` 不带参数） |

`DownloadOptions` 确实存在，但在 `Siemens.Engineering.Download` 命名空间，不属于编译。

## 2. 读 `CompilerResult`

```csharp
class CompilerResult {
    CompilerResultState            State        { get; }   // 总体结论
    int                            ErrorCount   { get; }
    int                            WarningCount { get; }
    CompilerResultMessageComposition Messages   { get; }   // 消息树
}

class CompilerResultMessage {
    CompilerResultState            State        { get; }
    string                         Description  { get; }   // 消息正文
    string                         Path         { get; }   // 出错对象路径
    DateTime                       DateTime     { get; }
    int                            ErrorCount   { get; }
    int                            WarningCount { get; }
    CompilerResultMessageComposition Messages   { get; }   // ← 可嵌套！
}
```

### `CompilerResultState` 四个取值

| 值 | 含义 |
| --- | --- |
| `Success` | 编译成功 |
| `Information` | 编译完成，有信息 |
| `Warning` | 编译完成，有告警 |
| `Error` | 编译有错误 |

### ⚠ `Messages` 是**嵌套树**，不是平表

每条 `CompilerResultMessage` 自己还有一个 `Messages` 集合。
只遍历第一层会漏掉深层诊断。

```powershell
function Get-FlattenedMessages {
    param($Messages, [string]$ParentPath = '')
    $out = @()
    foreach ($m in $Messages) {
        $path = if ([string]::IsNullOrWhiteSpace("$($m.Path)")) { $ParentPath } else { "$($m.Path)" }
        $out += [ordered]@{
            State       = "$($m.State)"
            Path        = $path
            Description = "$($m.Description)"
        }
        if ($m.Messages) { $out += Get-FlattenedMessages $m.Messages $path }
    }
    return $out
}
```

### 判成功 / 判失败

```powershell
# 唯一可靠的判据是 ErrorCount，不要用 State 字符串硬比
if ($result.ErrorCount -gt 0) { throw "Compile failed with $($result.ErrorCount) error(s)." }

# 注意：WarningCount > 0 时 State 会是 'Warning'，这是可接受的
```

### ⚠ 有些告警 Openness 不返回文本

本机实测：GRAPH 块编译返回 `State=Warning, ErrorCount=0, WarningCount=1`，
但 `Messages` 里**拿不到那条告警的文本**（`Description` 为空）。

遇到这种情况只能：
1. 接受它（`ErrorCount=0` 即视为通过），或
2. 在 TIA 界面里打开"编译结果"窗口看原文。

**不要**因为读不到文本就反复重试编译。

### `Compile()` 没有参数

不能指定"只编译某个块"或"重新编译全部"。
`ICompilable.Compile()` 编译该对象及其子树。
想只编译一个块，可以先 `GetService<ICompilable>()` 在**块对象**上
（`PlcBlock.GetService<T>()` 也存在）。

## 3. 完整编译脚本

```powershell
$PS51 = "$env:SystemRoot\System32\WindowsPowerShell\v1.0\powershell.exe"

& $PS51 -NoProfile -ExecutionPolicy Bypass -File .\examples\scripts\Invoke-TiaCompile.ps1 `
    -ProjectPath 'D:\Demos\MyProj\MyProj.ap20' `
    -ReportPath  'D:\out\compile.json' -FailOnError
```

输出：

```json
{
  "State": "Success",
  "Errors": 0,

  "Messages": [],
  "ProjectPath": "D:\\Demos\\MyProj\\MyProj.ap20",

```

`-FailOnError` 在有错误时 `exit 1`，方便接 CI。

## 4. 导出块 XML（模板挖掘）

这是逆向学习 SimaticML 的**核心手段**：

```powershell
& $PS51 -NoProfile -ExecutionPolicy Bypass -File .\examples\scripts\Export-BlockXml.ps1 `
    -ProjectPath     'D:\Ref\TrafficLight.ap20' `
    -OutputDirectory 'D:\Ref\exported' `
    -CompileFirst
```

```csharp
void Export(FileInfo path, ExportOptions exportOptions)
void Export(FileInfo path, ExportOptions exportOptions, DocumentInfoOptions documentInfoOptions)
DocumentExportResult ExportAsDocuments(DirectoryInfo directoryInfo, string fileNameWithoutExtension)
```

### `ExportOptions`

| 值 | 含义 |
| --- | --- |
| `None` | 导出时排除默认值和只读值（**最常用**） |
| `WithDefaults` | 包含默认值 |
| `WithReadOnly` | 包含只读值 |

### 三个坑

| # | 现象 | 原因 | 解决 |
| --- | --- | --- | --- |
| 1 | `file already exists` | TIA **拒绝覆盖**已存在的导出目标 | 导出前 `Remove-Item` 同名文件（脚本已内置） |
| 2 | `Inconsistent blocks … cannot be exported` | 块未编译 / 不一致 | 先编译（`-CompileFirst`），或检查 `PlcBlock.IsConsistent` |
| 3 | 导出成功但文件是空的 | 导出到了被占用的路径 | 用绝对路径，检查文件大小 |

### 只读导出，别改参考工程

导出**不需要** `Save()`。脚本默认不保存，
这样从别人的教程工程导出时，原工程的时间戳和内容都不会变。

### 导出的典型产物规模（本机实测）

| 块 | 语言 | 大小 |
| --- | --- | --- |
| `Main`（OB1，8 个网络） | LAD | 17,474 B |
| `GRAPH事件`（教程 GRAPH 块） | GRAPH | 68,315 B |
| `钻孔系统自动程序`（教程 GRAPH 块） | GRAPH | 83,834 B |
| `Graph_Sequencer`（自建，10 步/4 分支） | GRAPH | 78,000 B（导入用）/ 102,179 B（导出回） |

> 导出回的文件通常比导入用的大，因为 TIA 会补全默认值、
> 系统参数和多语言条目。

## 5. 备份策略

### 5.1 `.ap20` 文件很小，数据在旁边的目录里

```
MyProject\
├─ MyProject.ap20        ← 只有 ~150 KB，是个"指针"文件
├─ IM\  System\  Vci\  XRef\  Logs\  src\ …    ← 真正的数据在这里
```

**备份必须复制整个工程目录，不能只复制 `.ap20`。**

```powershell
function Backup-TiaProject {
    param($Project, [string]$BackupRoot)
    $projectDir = Split-Path -Parent $Project.Path.FullName
    if (-not $BackupRoot) { $BackupRoot = Join-Path (Split-Path -Parent $projectDir) '_backup' }
    New-Item -ItemType Directory -Force -Path $BackupRoot | Out-Null
    $target = Join-Path $BackupRoot ("{0}_{1}" -f $Project.Name, (Get-Date -Format 'yyyyMMdd-HHmmss'))
    Copy-Item -LiteralPath $projectDir -Destination $target -Recurse -Force
    return $target
}
```

仓库脚本统一用 `-Backup` 开关触发。

### 5.2 ⚠ 备份必须在"打开工程之前"或"改动之前"做

`Backup-TiaProject` 复制的是**磁盘上的状态**。
如果 TIA 已经打开了工程并做了未保存的修改，磁盘上还是旧的——
复制出来的是"改动前"的版本，这正好是我们要的。

**但反过来**：如果你先 `Save()` 再备份，备份里就已经含新改动了。

推荐顺序：

```
打开工程 → [备份] → 导入/修改 → 编译 → 校验 ErrorCount=0 → Save()
```

### 5.3 进程崩溃 = 数据丢失

`Save()` 之前所有改动只在内存里。TIA 无界面进程异常退出后：

- 设备、变量表、程序块全部丢失
- 重新打开工程会看到 `Device count: 0`

**所以：把长流程拆成"每步都 Save()"的小脚本**，
这样任何一步失败都不会丢掉前面已保存的成果。
本仓库的脚本都是这个设计（每个脚本结束时 `Save()` 一次）。

## 6. 变更前后对照

改动前跑一次 `Get-ProjectInventory.ps1`，改动后再跑一次，对比：

```powershell
& $PS51 -NoProfile -ExecutionPolicy Bypass -File .\examples\scripts\Get-ProjectInventory.ps1 `
    -ProjectPath 'D:\Demos\MyProj\MyProj.ap20' `
    -ReportPath  'D:\out\before.json'

# …执行改动…

& $PS51 -NoProfile -ExecutionPolicy Bypass -File .\examples\scripts\Get-ProjectInventory.ps1 `
    -ProjectPath 'D:\Demos\MyProj\MyProj.ap20' `
    -ReportPath  'D:\out\after.json'

# 然后 diff 两个 JSON
Compare-Object (Get-Content 'D:\out\before.json') (Get-Content 'D:\out\after.json')
```

清单包含：设备名 / 类型标识 / 是否有 PLC 软件 /
每个块的（名字、块号、语言、`IsConsistent`）/
每张变量表的（表名、变量名、数据类型、逻辑地址）/
以及 `Download` / `Online` 服务可用性。

## 7. SimaticML Schema 在哪、能告诉你什么

```
<Portal>\PublicAPI\V<xx>\Schemas\
├─ SW.Common_v3.xsd
├─ SW.InterfaceSections_v5.xsd
├─ SW.PlcBlocks.Access_v4.xsd
├─ SW.PlcBlocks.SCL_v3.xsd
├─ SW.PlcBlocks.LADFBD_v4.xsd
├─ SW.PlcBlocks.Graph_v5.xsd
├─ SW.PlcBlocks.STL_v4.xsd
├─ SW.PlcBlocks.CompileUnitCommon_v4.xsd
└─ …
```

### ⚠ XSD 的覆盖面比你想的窄

本机核对结论：

1. **所有这些 Schema 都没有 `targetNamespace`** —— 元素是不限定命名空间的。
   只有 `SW.TechnologicalObjects_*` 系列有真正的 `targetNamespace`。
   （XML 实例里的 `xmlns="http://www.siemens.com/automation/Openness/…"`
   是**实例文档**约定的，不是 XSD 里声明的。）

2. **本机安装里根本没有"块外壳"的 XSD。**
   全部 183 个 `.xsd` 里**没有任何一个**包含字符串 `SW.Blocks`。
   Schema 只覆盖到"块体"这一层（`Graph`、`FlgNet`、`StructuredText`、`StatementList`…）。
   → 所以 `<SW.Blocks.FB>` / `<SW.Blocks.OB>` 这些外壳标签的写法
   **只能从真实导出的样本学**，XSD 帮不了你。

3. **XSD 只保证"语法合法"，不保证"TIA 运行时接受"。**
   典型例子：空网络 `<Parts/><Wires/>` 完全符合 XSD，
   但 TIA 导入时报 *"Wires 的内容不完整。应为 Wire"*。
   同样，GRAPH 的分支相邻规则（见 [04 文档](04-GRAPH操作指南.md#5-分支拓扑规则全部经-tia-v20-导入实测)）
   在 XSD 里完全没有约束——`BranchRef` 只声明了 `In`/`Out` 两个可选 int 属性，
   什么连接合法一概没写。

**结论：XSD 用来查元素名和属性名；拓扑和运行时约束必须靠真实导出样本。**

### Schema 版本的一个反常现象（本机核对）

| 文件 | V18 载荷 | **V20 自带** | V19 载荷 | V21 |
| --- | --- | --- | --- | --- |
| Graph | v5 | **v5** | v6 | v6 |
| SCL | v3 | **v3** | v4 | v4 |
| Access | v4 | **v4** | v5 | v5 |
| LADFBD | v4 | **v4** | v5 | v5 |

- V20 自带 Schema 与 **V18 载荷逐字节相同**（SHA-256 一致）
- V19 载荷与 **V21 逐字节相同**
- GRAPH v5 → v6 **没有任何内容变化**，只有 `include` 目标从
  `Access_v4`/`LADFBD_v4` 换成 `_v5`
- SCL v3 → v4 同样只有 `include` 变化
- 唯一有实质内容变化的是 `Access v4 → v5`：
  `Access/@Scope` 从 **必填的受限枚举** 变成 **可选的无约束字符串**

> 实践含义：**不要用 schema 版本号推断 TIA 版本**。
> 写 XML 时以"你实际导出样本里的 `xmlns` 版本号"为准。
