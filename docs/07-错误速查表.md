# 07 - 报错速查表

> 全部条目都对应本机一次**真实**的报错与修复。按"环境 → 加载 → 工程 → SCL → GRAPH/LAD → 编译 → 导出"分组。

---

## A. 环境与授权

| # | 报错 / 现象 | 原因 | 解决 |
| --- | --- | --- | --- |
| A1 | `new TiaPortal(...)` 抛异常，提示无权限 / Openness 未授权 | 当前用户不在本地组 `Siemens TIA Openness` | `Add-LocalGroupMember -Group 'Siemens TIA Openness' -Member $env:USERNAME`，**注销并重新登录** |
| A2 | 首次运行弹授权对话框；或无人值守时直接失败 | 调用方 exe 未登记进 Openness 白名单 | 手工写 `HKLM\...\Openness\<ver>\Whitelist\<exe>\Entry`（Path / DateModified / FileHash），见 [01 文档](01-环境准备与授权.md#22-程序白名单whitelist-注册表) |
| A3 | **每次运行都重新弹授权** | exe 被重新编译/换了目录 → 路径或 SHA-256 变了 | 固定安装目录与文件名；不要每次改代码就换输出目录 |
| A4 | 在 V21 上调用报授权/白名单错误，但 V20 明明能用 | **V20 与 V21 的白名单是分开的**（`…\Openness\20.0\Whitelist` vs `…\Openness\21.0\Whitelist`） | 对 V21 单独授权一次 |
| A5 | `System.BadImageFormatException` | 用了 32 位宿主调用 64 位 Openness | 使用 64 位 `powershell.exe` |
| A6 | 加载 DLL 时 `FileNotFoundException`（找不到 Openness） | 装 TIA 时没勾选 "Openness" 安装包 | 重跑 TIA 安装程序，勾上 Openness |

## B. 加载 Openness 程序集（PowerShell 特有）

| # | 报错 / 现象 | 原因 | 解决 |
| --- | --- | --- | --- |
| B1 | `StackOverflowException`，进程直接崩溃 | 注册了 `AssemblyResolve` 手工解析依赖，递归回调进加载器 | **只** `[Reflection.Assembly]::LoadFrom($dll)`，删掉所有 AssemblyResolve 和依赖预加载 |
| B2 | `ReflectionTypeLoadException` | 用了 `Add-Type`，或在脚本**顶层**写了 `[Siemens.Engineering.X]` 强类型字面量——PS 在执行 `LoadFrom` **之前**就解析整个脚本 | 改为后期绑定 + 反射；枚举字面量只在**函数体内**、`LoadFrom` 之后使用 |
| B3 | `The property 'Siemens.Engineering.Base' cannot be found on this object` | 遍历注册表时枚举到了 `Whitelist` 等无关子键，直接取不存在属性；`Set-StrictMode -Version 2.0` 下会抛异常 | 先查 `$props.PSObject.Properties.Name -contains $name` 再取值；或用 `Set-StrictMode -Version 1.0` |
| B4 | 加载的是 **V18** 的 DLL，而不是 V20 | 同一个 Portal 会在注册表登记多个 API 版本（`17.0.0.0`…`20.0.0.0`），只按 Portal 版本排序会随机选中旧的 | 同时记录并排序 **API 版本号**（注册表子键名），取最高 |
| B5 | 在 PowerShell 7 里一切失败 | PS7 是 .NET Core，加载不了 .NET Framework 程序集 | 显式用 `"$env:SystemRoot\System32\WindowsPowerShell\v1.0\powershell.exe"` |
| B6 | 脚本报一堆 `Unexpected token` / `Missing closing '}'`，但代码看着没错 | **`.ps1` 存成无 BOM 的 UTF-8，PS 5.1 按 ANSI 读，中文注释被解码成乱码后破坏语法** | 把 `.ps1` 存成 **UTF-8 with BOM**（`[IO.File]::WriteAllText($p,$t,[Text.UTF8Encoding]::new($true))`） |

> **B6 是本机实际踩到的坑**：脚本在 `pwsh`（PS7，默认 UTF-8）下完全正常，
> 交给 PS 5.1 后因为 BOM 缺失导致中文字符串被拆坏，整个文件解析失败。
> 所有给 PS 5.1 用的脚本都必须带 BOM。

| # | 报错 / 现象 | 原因 | 解决 |
| --- | --- | --- | --- |
| B7 | `Get-Content -Raw` 读进来的 XML 解析失败，报 *start tag … does not match the end tag* | **同一个 BOM 根因的读侧**：PS 5.1 的 `Get-Content` 对无 BOM 文件按 ANSI 解码，多字节字符被破坏后**吞掉了相邻的 `<`** | 读文件统一用 `[IO.File]::ReadAllText($p, [Text.UTF8Encoding]::new($false))` |

> 📌 记住这条对称规律：
> **写 `.ps1` → 必须带 BOM；读无 BOM 的 UTF-8 文件 → 必须显式指定 UTF-8 编码。**

## C. 工程与会话

| # | 报错 / 现象 | 原因 | 解决 |
| --- | --- | --- | --- |
| C1 | 重开工程 `Device count: 0`，块/变量全没了 | 上次异常退出前没 `Save()`，改动只在内存 | 每完成一个阶段立即 `Save()`；把长流程拆成可续跑的小脚本 |
| C2 | 打开工程超时 / 报文件被占用 | 已有另一个 TIA 进程（GUI 或无界面）打开了同一工程 | 关掉多余进程；Openness 不会附着到 GUI 实例，而是另起一个 |
| C3 | 脚本超时（默认 60 s） | TIA **冷启动需要 1–3 分钟** | 把超时设到 ≥ 5 分钟；不要中途 kill（会留下残留进程） |
| C4 | 想调 `Projects.Open` 但 TIA 只停在启动页 → 超时 | 需要可附着的已打开工程会话 | 用 `TiaPortalMode.WithoutUserInterface` 自己起会话，别依赖 GUI |
| C5 | `CreateWithItem` 抛异常 | 订货号/固件版本不在本机硬件目录里 | 准备候选列表逐个 `try`；在 TIA 里查实际可用的订货号与固件版本 |
| C6 | `PlcSoftware not found` | 只遍历了 `device.DeviceItems` 第一层 | **广度优先遍历整个设备树**，在带 `SoftwareContainer` 服务的节点上取 `.Software` |
| C7 | `Devices.CreateWithItem` 成功但 `Get-PlcSoftware` 找不到 | 同上 | 同上 |

## D. SCL（外部源）

| # | 报错 / 现象 | 原因 | 解决 |
| --- | --- | --- | --- |
| D1 | `External source 'X' already exists` | 同名外部源不会被自动覆盖 | 先 `$src.Delete()`，或用 `Add-SclSource.ps1 -Replace` |
| D2 | `CreateFromFile` 参数异常 | 文件不存在 / 路径不合法 | 传**绝对路径**，先 `Test-Path` |
| D3 | 编译报某 `#Var` 未定义 | 接口段里没声明这个变量 | 在 `VAR` / `VAR_INPUT` / `VAR_OUTPUT` / `VAR_IN_OUT` 段里补声明 |
| D4 | 编译报某裸名字找不到 | 接口变量漏了 `#` 前缀，被当成全局符号查找 | 加 `#`：`#Start` 而不是 `Start` |
| D5 | 逻辑静默取错对象 | 接口变量名与全局变量**同名**（如都叫 `Motor_1`），裸名解析到全局那个 | 改名，或严格使用 `#` / `"…"` 区分 |
| D6 | 生成块成功但工程里没有 | 忘了 `$project.Save()` | 阶段末 `Save()` |
| D7 | 中文注释乱码 | 文件不是 UTF-8（被工具存成 GBK/ANSI） | 存成 UTF-8 with BOM |
| D8 | 语法报错但指不到具体位置 | 文件里有全角空格 / 零宽字符 / 混用行尾 | 清理非 ASCII 空白字符；行尾统一 |

## E. GRAPH 块 XML

> 这一组是最难的，来自本机 `GRAPH-实现问题记录.md` 的 18 条实测记录。

| # | 报错 / 现象 | 原因 | 解决 |
| --- | --- | --- | --- |
| E1 | `The action "Create block" only supports the programming language 'ProDiag'` | **`CreateFB` 不支持 GRAPH**（枚举里有 `GRAPH` 是假象） | GRAPH 只能走 XML 导入 |
| E2 | `Missing XML attribute 'ReadOnly' for attribute 'MemoryLayout'` | 手写了 `<MemoryLayout>` | 真实 GRAPH 块**没有**该元素 → 直接不写 |
| E3 | `Attribute 'xmlns' … mandatory in 'Graph'` | `<Graph>` 缺命名空间 | 加 `xmlns="…/NetworkSource/Graph/v5"` |
| E4 | `…Graph/v5 中的 "Supervision" 的子元素 FlgNet/v5 中的 "FlgNet" 无效` | 内层 `<FlgNet>` 带了别的命名空间 | 内层 `FlgNet` **不带任何 `xmlns`**，让它继承 |
| E5 | `"Wires" 的内容不完整。应为 "Wire"` | 空网络 `<Parts/><Wires/>` 被拒 | 每个网络至少 **1 个元件 + 1 条 Wire** |
| E6 | `"Step" 的内容不完整。应为 "Supervisions"` | Step 缺 `Supervisions`/`Interlocks` | 每步都必须有这两段（可以是最简网络） |
| E7 | `UId 为 503 的元素…需要线圈/分配` | 转换/互锁/监控网络用了普通 `Coil` | 用 **`TrCoil`** / **`IlCoil`** / **`SvCoil`**（它们只有 `in` 引脚，无操作数） |
| E8 | `instruction 'graphCoil' cannot be found` | `graphCoil` 是 TIA **界面内部符号名**，不是 XML 元件名 | 用真实导出里的 `TrCoil`/`IlCoil`/`SvCoil` |
| E9 | `All lines in the action table except for the last line must end with a line break` | 动作表行尾缺换行 | 每行尾加 `<Token Text="&#xA;" />`，表尾补一个空 `<Action />` |
| E10 | `The "…" sequencer does not start with a step` | 用 `Direct` 做闭环回跳，使初始步有了入口 | 闭环/跳转连接用 **`<LinkType>Jump</LinkType>`**；初始步（`Init="true"`）必须无入口转换 |
| E11 | `A connection between "Step3" and "Branch 2" cannot be created` | **选择分支的汇合节点不能直接接在步后面** | 支路末步先接各自转换，再由转换进 `AltEnd` |
| E12 | `A connection between "Trans2" and "Branch 1" cannot be created` | **选择分支的分叉节点不能接在转换后面** | 分叉节点直接挂在**步**下面 |
| E13 | `A connection between "Trans7" and "Branch 4" cannot be created` | **并行分支的汇合节点不能接在转换后面** | 每条并行支路用**结束步**收尾：`转换(结束条件) → 结束步 → SimEnd` |
| E14 | 并行分支拓扑怎么写都不对 | 并行分支的转换在分支**外面** | 分叉：`步 → 转换 → SimBegin → 步`；汇合：`SimEnd → 转换 → 步`；支路内只放步 |
| E15 | OB1 里调用 GRAPH 后编译 1 Error | 背景数据块的 `Instance Scope` 写成了 `LocalVariable` | 改为 **`Scope="GlobalVariable"`** |
| E16 | 导入后块的语言不是 GRAPH | `NetworkSource` 和 `AttributeList` 两处都要 `<ProgrammingLanguage>GRAPH</ProgrammingLanguage>` | 两处都写 |
| E17 | `<GraphVersion>` 缺失导致导入异常 | GRAPH 版本是必需属性 | 写 `<GraphVersion>6.0</GraphVersion>` |

### GRAPH 分支拓扑速记

```
选择分支 Alt（转换在分支"里面"）
  分叉:  步 --直接--> AltBegin
          AltBegin --Out i--> 转换 --> 步
  汇合:  步 --> 转换 --> AltEnd In i        ← 每条支路各带转换
          AltEnd --Out 0--> 步

并行分支 Sim（转换在分支"外面"）
  分叉:  步 --> 转换 --> SimBegin           ← 公共转换
          SimBegin --Out i--> 步            ← 支路内直接是步
  支路:  步 --> 转换（本支路结束条件）--> 结束步
  汇合:  结束步 --直接--> SimEnd In i       ← 结束步直接接汇合
          SimEnd --Out 0--> 转换 --> 步     ← 公共转换
```

## G. 编译与诊断

| # | 报错 / 现象 | 原因 | 解决 |
| --- | --- | --- | --- |
| G1 | 找不到 `CompileResult` / `CompileOptions` | **这两个类型不存在** | 正确名字是 `CompilerResult`；`Compile()` 不带参数 |
| G2 | `ICompilable service not available` | 在错误的宿主对象上取服务 | 服务要取在 `PlcSoftware` 上（块的 `GetService<T>()` 也可用） |
| G3 | `State=Warning` 让人以为失败 | `WarningCount>0` 时 `State` 就是 `Warning` | **判据用 `ErrorCount == 0`**，不要硬比 `State` 字符串 |
| G4 | `WarningCount=1` 但 `Messages` 里没有对应文本 | Openness 不返回某些告警的文本 | 接受（`ErrorCount=0`），或在 TIA"编译结果"窗口看原文；**不要反复重试** |
| G5 | 只能遍历到表层诊断，深层错误看不到 | `Messages` 是**嵌套树**，每条消息自身还有 `Messages` | 递归展平 |
| G6 | 编译 / 导入 / 导出莫名失败 | 这些操作**要求所有设备处于 Offline 状态** | 先下线；在线状态下写设备属性不被支持（读可以） |
| G7 | 拿不到错误文本，也不知道该不该继续 | 异常分两类 | **可恢复** `EngineeringException` 子类（`EngineeringSecurityException` / `EngineeringTargetInvocationException` / `EngineeringObjectDisposedException` / `EngineeringUserAbortException` …）→ 捕获后可继续<br>**不可恢复** `NonRecoverableException` → **TIA 会被关掉、连接断开，必须重启** |
| G8 | 块改不动、导出只有公共接口 | 块被**专有技术保护** | 先查 `$block.IsKnowHowProtected`，为 `true` 就跳过并提示 |
| G9 | 打开工程报缺产品 | 工程用到的选件/HSP 没装 | `MissingProductsException`；Openness **没有兼容模式**，工程用到的每个选件都必须安装 |
| G10 | `Projects.Open` 打不开旧版本工程 | `Open` 只能打开当前版本或已升级到当前版本的工程 | 用 **`Projects.OpenWithUpgrade`**；且只能升级"上一版"以内（V21 能开 `.ap20`/`.ap19`，开不了 `.ap16`） |

## G-bis. C# 应用特有（PowerShell 脚本不受影响）

| # | 报错 / 现象 | 原因 | 解决 |
| --- | --- | --- | --- |
| CB1 | `FileNotFoundException`：未能加载 `Siemens.Engineering…` | **程序在注册程序集解析器之前就引用了 Openness 类型**。.NET 是在**类加载**阶段（不是执行阶段）解析类型的，属性 / 方法参数 / 返回值里的 Openness 类型同样会触发 | `Main` 里**只注册解析器 + 加载 DLL**，把所有 Openness 代码放到**另一个类**，注册后再调用 |
| CB2 | 输出目录复制了一堆 Siemens DLL，行为诡异 | `Copy Local = True` | 所有 `Siemens.Engineering*` 引用设 **`Copy Local = False`**，并清理输出目录（程序集与 TIA 版本绑定、随安装位置变化） |
| CB3 | 换台机器就找不到 DLL | 硬编码了安装路径 | 从注册表读（见 [01 文档](01-环境准备与授权.md#4-自动定位-openness-程序集)） |

> 📌 **为什么本仓库的 PowerShell 脚本不需要折腾解析器**：
> 我们用的是 `[Reflection.Assembly]::LoadFrom($dll)` —— 加载的是**绝对路径**，
> 且脚本里**没有**顶层强类型引用，所以不存在"过早解析类型"的问题。
> 这两种场景的结论不同，不要互相套用。

## I. 通用排查顺序

遇到任何"跑不通"的问题，按这个顺序查：

```
1. 用的是不是 Windows PowerShell 5.1？
2. 当前用户在 'Siemens TIA Openness' 组里吗？重新登录过吗？
3. 调用方 exe 登记进白名单了吗？（路径 + 时间戳 + SHA-256 是否匹配）
4. .ps1 文件带 UTF-8 BOM 吗？（含中文时）
5. 有残留的 Siemens.Automation.Portal 进程吗？
6. 加载的是哪个版本、哪个路径的 Openness 程序集？（脚本日志第一行会打印）
7. 上一阶段 Save() 了吗？
8. 编译 ErrorCount 是多少？Messages 展平了吗？
9. 最后才是去查 XSD 和真实导出样本
```

前 8 条能解决绝大多数问题；第 9 条只在真正写 XML 时才需要。
