## 2. 授权：两道关卡

Openness 有两套**互相独立**的授权机制，缺任何一个都会在
`new TiaPortal(...)` 那一步直接抛异常。

### 2.1 Windows 本地用户组：`Siemens TIA Openness`

当前登录用户必须是这个本地组的成员，否则无法启动 Openness 会话。

```powershell
# 查看组是否存在、成员是谁
Get-LocalGroup | Where-Object Name -match 'Siemens'
Get-LocalGroupMember -Group 'Siemens TIA Openness'
```

本机实测输出：

```
Name                 Description
----                 -----------
Siemens TIA Openness Members of this group are authorized to execute external applications using TIA Portal Openness...

== Siemens TIA Openness
DESKTOP-UHIM51F\wei'ke
```

加入组（**需要管理员权限**）：

```powershell
Add-LocalGroupMember -Group 'Siemens TIA Openness' -Member $env:USERNAME
```

> ⚠ **加组后必须注销并重新登录 Windows**，组成员身份才会在新进程的令牌里生效。

### 2.2 程序白名单：`Whitelist` 注册表

Openness 只允许**登记过**的可执行文件调用它。第一次运行会弹一次授权对话框
（"是否允许此程序使用 TIA Portal Openness"），点"是"之后就登记到注册表。

注册表位置（版本号是 Openness 主版本）：

```
HKLM\SOFTWARE\Siemens\Automation\Openness\<版本>\Whitelist\<可执行文件名>\Entry
```

每个 `Entry` 有三个值：

| 值名 | 含义 |
| --- | --- |
| `Path` | 可执行文件的完整路径 |
| `DateModified` | 文件的最后修改时间（UTC，格式 `yyyy/MM/dd HH:mm:ss.fff`） |
| `FileHash` | 文件内容的 SHA-256，**Base64 编码** |

本机 `Whitelist` 实测内容（已登记 `powershell.exe`）：

```
HKLM\...\Openness\20.0\Whitelist\powershell.exe\Entry
    Path         = C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe
    DateModified = 2026/09/15 00:44:28.319
    FileHash     = i7b6jCg7TZISCx7ySamzEbD4BNTKu+mYEVmXbIvnal4=
```

> 💡 **这对我们非常有利**：只要用**系统自带的
> `C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe`** 跑脚本，
> 就复用同一条白名单记录。不要复制一份 powershell.exe 到别处用——
> 路径+哈希一变，TIA 会当成新程序重新弹窗。

#### 关于 `Entry (1)`、`Entry (2)`

同一个可执行文件可以有**多条** Entry。这是正常的：Windows 更新过
`powershell.exe`（哈希变了），重新授权时就追加了一条，
旧记录不会自动删除。TIA 匹配到任意一条即可。

#### 手工登记（自动弹窗失败时）

如果环境是无人值守、或弹窗被策略拦掉，可以手工写注册表（**管理员权限**）：

```powershell
$exe  = 'C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe'
$ver  = '20.0'
$info = Get-Item -LiteralPath $exe
$hash = [Convert]::ToBase64String(
            [System.Security.Cryptography.SHA256]::Create().ComputeHash(
                [IO.File]::ReadAllBytes($info.FullName)))

$entry = "HKLM:\SOFTWARE\Siemens\Automation\Openness\$ver\Whitelist\$($info.Name)\Entry"
New-Item -Path $entry -Force | Out-Null
Set-ItemProperty -Path $entry -Name Path         -Value $info.FullName
Set-ItemProperty -Path $entry -Name DateModified -Value $info.LastWriteTimeUtc.ToString('yyyy/MM/dd HH:mm:ss.fff')
Set-ItemProperty -Path $entry -Name FileHash     -Value $hash
```

**登记后要重启 TIA Portal。**

> ⚠ **千万不要**每次改代码都重新编译并换个新目录运行。
> 每次 exe 的路径/时间戳/SHA-256 变化，TIA 都会当成新应用再弹一次窗。
> 固定安装目录、固定文件名，是让授权"一次性通过"的关键。

## 3. Openness 程序集版本与布局（V20 vs V21）

这是最容易踩坑的地方，本机通过反射实测确认：

| | V20（及更早） | V21 |
| --- | --- | --- |
| 入口程序集 | `Siemens.Engineering.dll` | `Siemens.Engineering.Base.dll` |
| 子目录 | `PublicAPI\V20\` | `PublicAPI\V21\net48\` |
| 注册表值名 | `Siemens.Engineering` | `Siemens.Engineering.Base` |
| 程序集全名 | `Siemens.Engineering, Version=20.0.0.0, PublicKeyToken=d29ec89bac048f84` | `Siemens.Engineering.Base, Version=21.0.0.0, PublicKeyToken=29bfe5fdf4ba5d3b` |

V21 把原本一个大程序集**拆成了多个**：

| 程序集 | 内容 |
| --- | --- |
| `Siemens.Engineering.Base.dll` | 核心：`TiaPortal`、`TiaPortalMode`、`ICompilable`、`ImportOptions`、`ExportOptions` |
| `Siemens.Engineering.Step7.dll` | PLC：`SW.PlcSoftware`、`SW.Blocks.*`、`SW.ExternalSources.*` |
| `Siemens.Engineering.WinCC.dll` / `WinCCUnified.dll` | HMI |
| `Siemens.Engineering.Safety.dll` | 安全程序 |
| `Siemens.Engineering.Startdrive.dll` | 驱动 |

**实测结论**：只需要 `LoadFrom` **入口程序集**（`Siemens.Engineering.Base.dll`），
`Step7` 等其余程序集由 Openness 运行时按需解析，**不要手工预加载**。

V20 实测类型分布（`Siemens.Engineering.dll`，共 2117 个导出类型）：

```
TiaPortal                                      ← 就在这一个 DLL 里
Siemens.Engineering.SW.PlcSoftware             ← 也在
Siemens.Engineering.SW.Blocks.PlcBlockComposition
Siemens.Engineering.SW.ExternalSources.PlcExternalSource
Siemens.Engineering.Compiler.ICompilable
Siemens.Engineering.ImportOptions
Siemens.Engineering.ExportOptions
```

V21 实测：

```
Siemens.Engineering.Base.dll    → 有 TiaPortal / ICompilable / ImportOptions / ExportOptions
                                → 没有 SW.* 类型
Siemens.Engineering.Step7.dll   → 有 SW.PlcSoftware / SW.Blocks.* / SW.ExternalSources.*
                                → 没有 ICompilable / ImportOptions
```

### `ProgrammingLanguage` 枚举

```csharp
// V20
Undef, STL, LAD, FBD, SCL, DB, GRAPH, CPU_DB, CFC, SFC, FBD_IEC, LAD_IEC,
SDB, S7_PDIAG, RSE, F_STL, F_LAD, F_FBD, F_DB, F_LAD_LIB, F_FBD_LIB,
FCP, FLD, ProDiag, ProDiag_OB, Motion_DB, F_CALL, CEM

// V21  多了一个 ST（Structured Text）
… 同 V20 … , CEM, ST
```

> `GRAPH` 在枚举里**存在**，但这**不代表**你能用它建块——见

## 4. 自动定位 Openness 程序集

不要硬编码路径。注册表里有权威记录：

```
HKLM\SOFTWARE\Siemens\Automation\Openness\<主版本>\PublicAPI\<完整版本>\
     值名 Siemens.Engineering      → DLL 路径        (V13–V20)
HKLM\SOFTWARE\Siemens\Automation\Openness\<主版本>\PublicAPI\<完整版本>\net48\
     值名 Siemens.Engineering.Base → DLL 路径        (V21+)
```

本机实测（V20，注意同时存在于 64 位和 WOW6432Node 两个视图下）：

```
HKEY_LOCAL_MACHINE\SOFTWARE\Siemens\Automation\Openness\20.0\PublicAPI\20.0.0.0
    Siemens.Engineering = D:\Program Files\Siemens\Automation\Portal V20\PublicAPI\V20\Siemens.Engineering.dll
HKEY_LOCAL_MACHINE\SOFTWARE\Siemens\Automation\Openness\20.0\PublicAPI\19.0.0.0
    Siemens.Engineering = D:\Program Files\Siemens\Automation\Portal V20\PublicAPI\V19\Siemens.Engineering.dll
```

（同一个 Portal V20 安装会同时登记 V17/V18/V19/V20 四个 API 版本，
因为它是向下兼容的多版本 API。）

V21 实测：

```
HKEY_LOCAL_MACHINE\SOFTWARE\Siemens\Automation\Openness\21.0\PublicAPI\21.0.0.0\net48
    AssemblyVersion          = 21.0.0.0
    PublicKeyToken           = 29bfe5fdf4ba5d3b
    Siemens.Engineering.Base = D:\Program Files\Siemens\Automation\Portal V21\PublicAPI\V21\net48\Siemens.Engineering.Base.dll
```

> ⚠ V21 的白名单键在 `…\Openness\21.0\Whitelist`，
> 和 V20 的 `…\Openness\20.0\Whitelist` **是分开的**——
> 用 V21 API 要单独授权一次。

仓库里的 `Resolve-OpennessAssembly`（见
[`examples/scripts/Openness.Common.ps1`](../examples/scripts/Openness.Common.ps1)）
把上面这些差异全部封好了：

```powershell
# 取本机最高版本
Resolve-OpennessAssembly

# 只要 V20
Resolve-OpennessAssembly -PortalVersion 20

# 只要 V21
Resolve-OpennessAssembly -PortalVersion 21
```

## 5. 运行时宿主选择

| 宿主 | 能否加载 Openness | 说明 |
| --- | --- | --- |
| **Windows PowerShell 5.1** | ✅ 可以 | `%SystemRoot%\System32\WindowsPowerShell\v1.0\powershell.exe`，.NET Framework 4.x |
| PowerShell 7 / pwsh | ❌ 不行 | .NET Core，加载 .NET Framework 程序集失败 |
| .NET Framework 4.8 控制台/exe | ✅ 可以 | 需要 x64 |
| .NET 6/8 | ❌ 不行 | 同上 |

**必须显式调用 5.1**，因为很多机器上 `powershell`/`pwsh` 默认已经解析到 7.x：

```powershell
& "$env:SystemRoot\System32\WindowsPowerShell\v1.0\powershell.exe" `
    -NoProfile -ExecutionPolicy Bypass -File .\Add-SclSource.ps1 -ProjectPath ... -SclPath ...
```

`-NoProfile` 建议加上：用户 profile 里若有 `Set-StrictMode` 或自定义
`$ErrorActionPreference`，会干扰脚本行为。

## 6. 加载程序集的正确姿势

```powershell
# ✅ 唯一推荐的写法：只加载一个入口 DLL
[System.Reflection.Assembly]::LoadFrom($opennessDll) | Out-Null
```

**不要**做下面这些事（本机实测会导致进程崩溃）：

| 反模式 | 后果 |
| --- | --- |
| 注册 `AppDomain.CurrentDomain.add_AssemblyResolve` 手工解析依赖 | **`StackOverflowException`** —— 解析器递归回调进加载器 |
| 手工预加载 `Contract` / `ClientAdapter` 等内部程序集 | 同上，且可能污染绑定上下文 |
| 在 PowerShell 脚本顶部写强类型 `[Siemens.Engineering.TiaPortal]` 参数 | **`ReflectionTypeLoadException`** —— Windows PowerShell 在 `Add-Type`/`LoadFrom` 执行**之前**就解析整个脚本的所有类型字面量，此时类型还不存在 |

最后一条是 PowerShell 特有的大坑，也是为什么本仓库所有脚本都用
**late-bound（后期绑定）+ 反射** 的写法：

```powershell
# ❌ 不行：脚本解析阶段就要解析 [Siemens.Engineering.TiaPortalMode]，那时 DLL 还没加载
function Connect { param([Siemens.Engineering.TiaPortalMode]$Mode) ... }

# ✅ 可以：运行时才解析
$mode = 'WithoutUserInterface'
$tia  = New-Object Siemens.Engineering.TiaPortal([Siemens.Engineering.TiaPortalMode]::$mode)

# ✅ 泛型方法必须反射调用（PS 5.1 无法直接写泛型参数）
$method = $instance.GetType().GetMethods() |
    Where-Object { $_.Name -eq 'GetService' -and $_.IsGenericMethodDefinition -and
                   $_.GetParameters().Count -eq 0 } | Select-Object -First 1
$service = $method.MakeGenericMethod($serviceType).Invoke($instance, $null)
```

> 例外：**枚举类型字面量**（`[Siemens.Engineering.ImportOptions]::Override`）
> 在**函数体内**、且放在 `LoadFrom` 之后执行时是可以的，
> 因为函数体是调用时才解析。本仓库脚本就是这么用的。

## 7. TIA Portal 进程模型

| 事实 | 影响 |
| --- | --- |
| `TiaPortalMode.WithoutUserInterface` | 启动一个**无界面**的 TIA 进程，适合自动化 |
| `TiaPortalMode.WithUserInterface` | 带界面启动 |
| Openness **不会**附着到已经在运行的 GUI 版 TIA | 会另起一个进程 |
| 同一工程被两个进程打开 → 互相锁定 | `.ap20` 被占用，报错或超时 |
| 冷启动通常 **1–3 分钟** | 脚本超时请设 ≥ 5 分钟；不要中途 kill |
| 脚本异常退出会留下**残留进程** | 下次运行前先检查/清理 |

运行前检查残留进程：

```powershell
Get-Process -Name 'Siemens.Automation.Portal' -ErrorAction SilentlyContinue |
    Select-Object Id, ProcessName, StartTime
```

> ⚠ **异常退出的最大后果不是报错，而是"数据没保存"。**
> 设备、变量、块在 `Project.Save()` 之前只存在于内存里。
> 重新打开工程会看到 `Device count: 0`，让人以为"块丢了"。
> → **每个阶段结束都 `Save()` 一次**，把长流程拆成可续跑的小步骤。

## 8. 环境自检清单

跑任何自动化之前，按顺序确认：

```powershell
# 1) 必须用 5.1
$PSVersionTable.PSVersion            # 期望 5.1.x

# 2) Openness 是否安装、入口程序集在哪里
Get-ChildItem 'HKLM:\SOFTWARE\Siemens\Automation\Openness' |
    ForEach-Object { $_.PSChildName }                     # 期望看到 20.0 / 21.0

# 3) 用户组
(Get-LocalGroupMember 'Siemens TIA Openness').Name         # 期望包含当前用户

# 4) 白名单
Get-ChildItem 'HKLM:\SOFTWARE\Siemens\Automation\Openness\20.0\Whitelist' |
    ForEach-Object { $_.PSChildName }                      # 期望包含 powershell.exe

# 5) 没有残留 TIA 进程
Get-Process -Name 'Siemens.Automation.Portal' -ErrorAction SilentlyContinue

# 6) 硬件目录里有你要的 CPU
#    用 New-TiaProject.ps1 -OrderNumbers/-Versions 逐个试，日志里会打印哪个可用
```

仓库脚本 `Get-ProjectInventory.ps1` 可一次性输出第 5 项之外的所有运行时信息。
