# 三电机 LAD 修正实现记录

日期：2026-10-06。

## 问题 → 原因 → 解决

旧版本停止按钮直接清除运行锁存，输出依赖该锁存，导致同时停机；停止定时器直接依赖按钮，短脉冲无法完成序列。另一 SCL 修正版在停止时复位启动 TON，Motor2 又依赖 Start2.Q，也会立即停止。

本次采用独立电机运行状态 `M2.0/M2.1/M2.2` 的置位/复位线圈。启动 TON 的 Q 仅负责置位后续电机，不能直接作为电机保持条件。停止请求 `M3.0` 单独锁存至全部电机停止；记录停机前最高运行电机快照，立即停当前最后启动电机，随后按实际剩余电机逐级执行两个 2 秒 TON。启动按钮上升沿通过 `M4.0/M4.1` 形成，拒绝长按自动重启。

新增 S7-1500 工程，最终采用 PLCSIM Advanced Runtime API 实测。最终控制代码是 LAD FB，SCL 仅用于获得正确的四个多重实例 TON_TIME 接口；导入后 OB1 LAD 调用该 FB 与背景 DB。原历史工程未改变。

## 本轮新增报错与修复

- `The connection named 'out' at the part with UId '128' is used multiple times at the cables.`：FlgNet 同一源引脚扇出必须合并到同一 Wire，生成器现已合并。
- `The argument 'SecondaryType' is missing.`：OB1 添加 `<SecondaryType>ProgramCycle</SecondaryType>`。
- C# helper 找不到 `DownloadConfiguration`：增加 `using Siemens.Engineering.Download.Configurations;`。
- 下载报 `An error has occured during download: '硬件配置编译完成，但出现错误。'`：软件编译成功不等于硬件可下载。递归展开 CompilerResult.Messages 后发现 3 个硬件安全配置错误：

```text
If access control via access level is enabled and a higher access level (= access without login) than full access (no protection) is set, the password for full access (no protection) must be set.
Password for confidential PLC configuration data is not configured in the PLC.
The PLC communication certificate cannot be configured without the password for confidential PLC configuration data. Enter the password.
```

  设置本仿真 CPU 为 FullAccess；`PlcMasterSecretConfigurator.Unprotect()` 将 MasterSecretConfiguration 从 WithoutPassword 改为 None。重新编译 0 错误，成功下载。编译报告工具原来仅读取一级 Messages，已修改为递归收集，保留 Depth/Path/Description。
- PS5.1 读取无 BOM 中文脚本报 `The string is missing the terminator: '.`：脚本统一保存 UTF-8 BOM。
- `CreateInterface` 报 `Error Code: -4, DoesNotExist`：探测脚本退出后，不能假定该 API 客户端注册的实例仍存在。正式测试脚本检查 RegisteredInstanceInfo，必要时重新注册，在同一进程中 PowerOn、Run、读写。交互展示脚本保持客户端存活。
- 非 TTY 会话 `write_stdin failed: stdin is closed for this session; rerun exec_command with tty=true to keep stdin open`：下载重试改为显式 `-InteractiveRetry`，默认失败立即退出；展示脚本使用 TTY。排障时只结束本次创建的无界面脚本和对应 TIA 进程。

## 开源方案如何操作，以及适用边界

1. [PLCsim-Advanced-Manager](https://github.com/jasperdekeuk/PLCsim-Advanced-Manager)：已只读克隆并研究源码，实际 commit `4b4947828c2537f1314a2e039a59b50e73407f9f`，MIT。`Services/InstanceHandler.cs` 管理注册实例；`Services/Nodegraph/NodegraphService.cs` 使用 PowerOn、Run、ReadSignals、WriteSignals。这是 Advanced API 的管理封装，仍需要 Siemens Runtime 和许可。本次直接调用同一 API，无需启动它的 Web 服务或安装第三方管理程序。第三方源码未复制到发布仓库。
2. [OpenPLC Runtime](https://github.com/Autonomy-Logic/openplc-runtime)：可无界面运行 IEC 61131-3 程序；其 README 给出 Docker 路线及 REST 工作流，Editor 编译并打包 program.zip，上传 `/api/upload-file`，轮询 `/api/compilation-status`，通过 `/api/start-plc`、`/api/stop-plc` 控制运行。它执行 OpenPLC 生成的程序；若改走此路线，需要移植控制逻辑，不能把本次 `.ap20` 或 Siemens 下载卡作为已验证兼容的输入。本机没有安装或执行 OpenPLC，因为 Advanced 原生路线已经通过。
3. [awlsim](https://github.com/mbuesch/awlsim)：自由的 AWL/STL、FUP/FBD 模拟器，CPU 模型主要对应 S7-3xx/4xx。其 README 指导克隆、获取子模块、运行 examples/EXAMPLE.awlpro。适合另写经典 STEP7 指令级示例，不能用其结果替代本次 S7-1500 LAD/TON_TIME 的真实验证。本次未安装/执行。

官方依据：[Openness 下载 PLC 到 Windows 文件夹](https://docs.tia.siemens.cloud/r/en-us/v20/tia-portal-openness-api-for-automation-of-engineering-workflows/tia-portal-openness-api/functions-for-accessing-the-data-of-a-plc-device/functions-for-downloading-data-to-plc-device/downloading-plc-to-a-windows-folder)、[Test Suite 运行示例](https://docs.tia.siemens.cloud/r/en-us/v20/tia-portal-test-suite/openness-support/functions-for-application-test/execution-of-test-cases)、[Access level setting](https://docs.tia.siemens.cloud/r/en-us/v20/tia-portal-openness-api-for-automation-of-engineering-workflows/tia-portal-openness-api/functions-for-accessing-the-data-of-a-plc-device/functions-for-accessing-plc-service/access-level-setting)。Test Suite 示例说明虚拟卡注册与运行步骤；本次直接调用 Runtime API，没有调用 TestSuiteExecutor。
